# 项目背景与愿景（长期记忆）

> 来源：创始人与 ChatGPT 的一次完整讨论（分享链接 `6a841807-1be4-83ea-aef7-96c676bb1dd0`，对话时间 2026-08-05）。
> 状态：本文是**愿景与讨论记录**，目的是给后续 Agent 与协作者提供统一的项目背景理解；其中市场数据与商业假设属于讨论素材，**未经验证前不得当作既定事实**，落地为需求/架构/决策时需另行确认并写入 ADR。

---

## 一、一句话定位

做一个**笼养宠物（先以小型鹦鹉为切入点）的“Oura Ring + 家庭监控管家”**：把一天十几个小时的笼内视频与声音，压缩成几分钟能读懂的行为日报，并在宠物明显偏离其“个人基线”时提醒主人。

它不替主人天天看直播，而是回答：

> 今天它吃了几次、什么时候最活跃、和同伴互动怎么样、昨晚有没有被惊醒、哪些行为和平常不一样、哪些片段值得我亲自回看。

---

## 二、起点与创始人背景

- 创始人背景：HCI + 产品经理，计划以**一人公司**方式推进。
- 现实起点：自家养了**两只牡丹鹦鹉**，其中一只蓝色、名叫 **Lumi**（被当作“零号用户和第一位产品经理”）。
- 已具备的硬件条件：笼内装有**鱼眼摄像头，几乎从正上方俯拍**，可覆盖笼内绝大部分画面并收录声音。
- 创始人的核心产品信条（在讨论中反复出现）：
  > 不要做“用户打开 ChatGPT 就能完成的事情”，而要做一整套完整的工作流。

## 三、核心产品定义与 MVP

### 产品定义

**“鹦鹉日常行为记录与异常提醒工具”**。第一版只回答三个问题：

1. 鸟今天做了什么；
2. 和它自己平时相比，有没有明显变化；
3. 哪些变化值得主人回看或关注。

第一版**不**做：情绪判断、爱不爱另一只鸟、想要什么玩具、疾病诊断。这些只能作为后续推断，不能作为底层能力。

### MVP 范围（讨论中收敛的结论）

**三项识别 + 一份日报 + 异常视频回看**：

1. 食盆访问（靠近/啄食/停留时长/访问次数）；
2. 活动量与长时间静止；
3. 多鸟靠近与互动（理毛/追逐/争抢/分开休息）。

每天生成：活动曲线、进食次数、社交时长、异常事件、以及 30 秒—2 分钟的“今日精选”。

暂时不做：精确情绪、疾病诊断、鸟语翻译、自动推荐饮食/玩具、精确睡眠分期、全鸟种通用。

**第一版甚至可以只针对：固定笼子、固定摄像头、1—2 只牡丹鹦鹉。范围越窄越有机会跑起来。**

### 关键能力拆解

- 可观察行为识别（进食、饮水、睡眠/休息、活动量、社交互动、鸣叫与声音异常、身体姿态异常），控制在 5—7 类，不要一开始做二三十种。
- **个体基线**：记录 7—14 天后，为每只鸟建立“自己的正常”，异常是和**这只鸟自己**比，不是和“标准鹦鹉”比。这是产品的壁垒之一。
- **大模型解释层**：大模型只负责把结构化结果翻译成人话，不负责底层识别。

### 个体身份识别

- 多鸟外观相似时，个体追踪是难点（飞得快、遮挡、鱼眼畸变、夜间、出画）。
- 现实 MVP 方案：**给每只鸟佩戴不同颜色的安全脚环**，模型优先检测脚环颜色 + 身体位置做追踪。
- 不愿戴脚环时，第一版可退化为“只分析笼子整体状态，不区分个体”。

## 四、技术结构（五层，讨论稿）

```text
摄像头采集 → 鸟检测与追踪 → 行为事件识别 → 个体基线 → 大模型解释层
```

1. **摄像头采集**：24 小时视频 + 音频 + 时间（可加温湿度/光照）。不建议第一版把全天原视频上传云端；先本地低码率录制、隔秒抽帧、检测到事件时保存前后 15—30 秒。
2. **鸟检测与追踪**：是否有鸟、位置、所在区域、轨迹、是否靠近食盆/水盆/栖木/笼底。关键是先在画面中标出**功能区**（食盆区、水盆区、睡觉栖木、笼底、玩具区）。
3. **行为事件识别**：输出结构化事件（`Bird A entered food zone / stayed 42s`），而非自然语言情绪。事件可保存、统计、复盘。
4. **个体基线**：每日活动时间、食盆访问次数、夜间静止时长、鸣叫频率、社交时长、长时间静止次数。
5. **大模型解释层**：把结构化指标（如 `food_visits_change: -35`）翻译成日报文案。

## 五、关键战略方向（讨论中收敛，落地前需确认）

1. **先做鹦鹉，不做猫狗**：真正要复用的是“长期视频+声音 → 行为基线 → 异常发现 → 可读报告”的整条 Pipeline（约 70% 可复用）；只有“行为识别模型”需要重训。笼内动物（固定空间、摄像头覆盖完整、行为稳定）在 CV 上比猫狗更容易，且竞争少、用户重度。
2. **不做硬件**：走“摄像头无关（Camera Agnostic）”路线，兼容 RTSP/ONVIF 的通用 IP 摄像头（Tapo、Reolink、Dahua、Hikvision 等），甚至支持旧手机当摄像头；卖“第二层智能”，不卖“第一层摄像头”。
3. **扩张路径**：牡丹鹦鹉 → 小型鹦鹉 → 全部家养鹦鹉 → 仓鼠/花枝鼠/豚鼠/龙猫 → 兔子 → 笼养宠物行为平台 → 最后才选择性进入猫狗。
4. **平台定位**：把自己定位成 **Animal Behavior Intelligence（动物行为智能）平台**，鹦鹉只是第一个验证场景。名字倾向 “Bird Intelligence / Pet Behavior AI”，而不是 “Bird Camera”。

## 六、关键洞察（来自对真实图片的分析）

- **先理解环境，再找鸟**：模型第一步是理解笼子的“语义”（食盆、水盆、玩具、栖木、笼底），而不是先做鸟识别。首次安装时 AI 自动识别功能区并让用户确认即可。
- **“事件（Event）”才是产品核心**：系统输出的是结构化的行为时间线（`11:42 Lumi 进入食盆，停留 48 秒`），这才是用户真正关心的东西；产品因此更接近“动物行为记录系统”而非“图像识别产品”。
- **正上方鱼眼视角对 AI 比对人更友好**：即使鸟头被玩具挡住，身体轮廓仍在，利于持续追踪。
- **日报要满足两种需求**：健康安全感 + 情感陪伴（“我错过了什么”）。只做健康监控，用户只有担心时才打开；加入每日精彩片段，正常日子也有打开理由。

## 七、市场与商业模式（讨论稿，数据需重新核实）

### 市场规模要点

- 美国：约 600 万家庭养鸟、约 600 万家庭养小型动物（兔子 37%、豚鼠 23%、仓鼠 18%）；Z 世代占小型动物主人 34%（APPA 2025）。
- 欧洲：约 4800 万只观赏鸟、2500 万只小型哺乳动物（FEDIAF 2025，注意是动物数不是家庭数）。
- 中国：受访宠主中鸟类 8.7%、啮齿类 7.6%；观赏鸟中鹦鹉占 60.1%（《2026 中国宠物行业白皮书》公开摘要）。
- 结论：不是猫狗级别的大市场，但也不是微型市场，属于“足够养活一家高毛利小公司的深度垂直市场”。

### 盈利模式

1. **家庭订阅（核心）**：按家庭/摄像头收费，不按只数。免费版（实时查看、少量事件、3 天历史、1 只档案）→ Plus（约 $5.99–7.99/月，完整日报、30 天趋势、个体识别、异常提醒、家庭成员共享）→ Care（约 $11.99–14.99/月，90 天+趋势、兽医报告、多摄像头多宠物、异常声音分析）。
2. **兽医报告/健康档案**：一键生成“最近 N 天行为记录报告 + 关键片段”，单次 $5–15 或含在高阶订阅；明确定位为**行为记录报告，非诊断证明**。
3. **B2B**：繁育者、寄养、救助站、宠物店、异宠医院（多笼管理、异常笼位提醒、批量日报、长期录像检索），按笼位/摄像头或机构套餐收费。
4. **硬件与用品导购**：推荐测试过的摄像头/传感器/玩具（带佣金），但需与订阅分开、标注佣金、不夸大动物意愿。

### 阶段目标（商业假设）

- 1000 付费用户 = 证明需求；5000 = 不错的一人公司；2 万 = 成功的垂直 SaaS；10 万 = 需跨物种与团队。
- 按 $7/月估算：5000 人 ≈ $42 万/年，2 万人 ≈ $168 万/年。
- 现实追求：先做到 **5000—20000 个高度投入、续费稳定的家庭**。

### 竞争格局

- 现有鹦鹉 App（BirdCare、Bird Tracker、Patapata、BirdTricks 等）多为**人工记录**体重/饮食/用药/训练。
- 猫狗摄像头（Furbo、Petcube、Whisker、Tractive、Fi、Petivity）商业模式已验证，但识别体系围绕猫狗，不覆盖笼养宠物的进食/栖息/社交行为。
- 缺口：**自动读取笼内连续视频、建立个体行为基线、生成可回看日报**的成熟产品目前缺位。

## 八、已知实体与环境事实（来自讨论，用于产品语境）

- 宠物：两只牡丹鹦鹉，一只蓝色名为 **Lumi**（另有一只，讨论中未始终明确其名字）。
- 摄像头：鱼眼，几乎正上方俯拍，能覆盖笼内大部分区域并录音。
- 笼内功能区（图片中已确认的布局）：
  - 主食区：右侧中下部的种子/谷物食盒；
  - 疑似饮水区：右上透明容器（需进一步确认是水盒/浴盆/空食盒）；
  - 绳圈玩耍区：左侧大型麻绳圆环 + 挂件（攀爬/啃咬/互动）；
  - 撕咬探索区：顶部纸质玩具 + 木平台；
  - 栖木与通行区：左上方白色弯曲栖木 + 下方横杆；
  - 笼底区：健康风险高价值区域（长时间待在笼底应高优先级提醒）。

## 十、安全与责任边界（沿用仓库既有要求）

- 动物疾病识别、用药与处置属于高风险业务：自动化输出必须保留证据来源，并在实际执行前由具备资质的人员复核。
- 健康预警、异常呼吸音等只能提示“疑似”，不得直接表述为确定诊断。
- 不得自动执行用药和高风险处置；外部消息发送、数据删除及不可逆操作需明确授权。
- 本文中的市场数据、商业假设和“可行/不可行”判断均来自一次讨论，须验证后才可作为设计与决策依据。
