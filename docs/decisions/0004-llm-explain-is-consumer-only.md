# 0004：大模型只作为「解释层 Consumer」，不进入识别引擎

- 状态：Accepted
- 日期：2026-08-18
- 决策者：项目负责人

## 背景

创始人的核心产品信条之一是：**不要做「用户打开 ChatGPT 就能完成的事情」，而要做一整套完整的工作流**（见 `docs/project-background.md`）。

`docs/project-background.md` 明确把大模型的职责限定为：**只负责把结构化结果翻译成人话，不负责底层识别**。底层识别（食盆访问、活动量、多鸟互动、鸣叫异常）由 CV/信号处理模型完成，输出结构化事件（如 `Bird A entered food zone / stayed 42s`），大模型在此基础上生成日报文案。

这个边界若只靠「自觉」维持，很容易被突破：例如为了让日报「更聪明」，直接把原始帧/音频塞给多模态模型做端到端判断。这会导致三类问题：

1. **不可追溯**：端到端判断是黑盒，无法回答「结论由哪条事件、哪版规则/模型产生」，违反 ADR-0001。
2. **成本与延迟不可控**：全天视频/音频直送大模型成本高、延迟大、结果不稳定，与「本地抽帧、事件驱动」的架构矛盾。
3. **不可测试、不可重放**：黑盒输出无法用确定性输入回放验证。

## 决策

**大模型只作为 `explain` 接缝的 Consumer：其输入是结构化指标/偏差（`metrics` + `deviations`），输出是人话日报文案；绝不接受原始帧或原始音频。底层识别由 `detect`/`behavior` 接缝完成。**

### 职责边界（用类型与测试强制，而非仅靠规范）

| 层 | 输入 | 输出 | 是否可进 LLM |
|---|---|---|---|
| `detect` / `behavior` | 帧、轨迹 | 结构化行为事件 | 否（CV/信号模型，确定性优先） |
| `baseline` | 事件流 | 指标 + `Deviation` | 否（统计投影） |
| `explain` | `metrics` + `deviations`（结构化） | 日报/报告文案 | **是（唯一允许点）** |

### 三条硬规则

1. **`explain` 的类型签名不接受原始媒体**：只接受结构化的 `metrics`/`deviations`（已由事件日志投影而来）；传入 `Frame`/`AudioChunk` 在类型层面即失败。
2. **必须有确定性兜底 Provider**：`TemplateProvider` 在不依赖任何 LLM 的情况下，用模板把结构化指标渲染成可读日报。这保证无 key/离线/LLM 故障时仍能产出日报，并作为 LLM 输出的对照基线。
3. **LLM 输出不改变事实**：日报文案只是对既有结构化结论的「翻译与措辞」，不得新增、删除或改写事实指标；涉及健康风险的措辞只能「疑似/提示」，不得表述为确定诊断（与 `AGENTS.md` 安全边界一致）。

### 与接缝的关系

`explain` 是 ADR-0002 中五个接缝之一，遵循同一「Definition/Provider/Consumer」结构：`ExplainProvider` 抽象基类 + `DeepSeekProvider` / `LocalLLMProvider` / `TemplateProvider` 三个 Provider + 日报/兽医报告 Consumer。Consumer（日报生成器）只依赖 `ExplainProvider` 抽象，不依赖具体 LLM Provider。

## 备选方案

### 方案 A：端到端多模态模型直接识别 + 生成（未采用）

把视频/音频片段直接交给多模态 LLM，让它判断行为并写日报。

- 优点：开发快、上限高（潜在可识别更多行为）。
- 缺点：黑盒、不可追溯、成本高、不稳定、难测试；违背「结构化事件才是产品核心」与 ADR-0001。可作为后续「非底层能力」的探索方向，但不作为 MVP 识别层。

### 方案 B：LLM 既做识别也做解释（混合，未采用）

让 LLM 在结构化事件之上再做一次「语义增强」，把事件进一步聚合成「行为叙事」，再写日报。

- 优点：日报更自然。
- 缺点：若「语义增强」引入了新的事实判断，就破坏了可追溯边界；若只是措辞，则与 `explain` 等价。为避免边界模糊，MVP 采用纯解释，不引入「LLM 参与事实判断」的中间层。

### 方案 C：完全不用 LLM，只用模板（未采用）

只用 `TemplateProvider` 出日报。

- 优点：最确定、最便宜。
- 缺点：日报呆板，无法满足「情感陪伴 + 健康安全感」的产品诉求。故保留 LLM，但以模板为确定性兜底。

## 影响

**正面：**

- 可追溯：日报的每个结论都来自结构化事件与指标，可回溯（对齐 ADR-0001）。
- 可测试：`explain` 输入确定、可回放；`TemplateProvider` 提供确定性基线。
- 成本可控：LLM 只处理压缩后的结构化指标，不处理媒体。
- 稳定：LLM 故障/无 key 时仍能出日报。

**代价与风险：**

- 日报「智能感」受限于结构化指标的表达力，需要先做对识别层，解释层才有料可用。
- 若未来发现某些行为确实难以结构化，需要重新评估边界（届时另立 ADR，而非悄悄把媒体塞给 LLM）。

**后续工作：**

- 定义 `explain` 输入的结构化 schema（`metrics` + `deviations`，与 ADR-0003 的 `Deviation` 对齐）。
- 实现 `TemplateProvider` 作为首个确定性 Provider。
- 明确健康风险措辞模板与「疑似/提示」的用词规范。

## 验证

- 类型边界：测试断言 `ExplainProvider.render()` 的签名不接受 `Frame`/`AudioChunk`，只接受结构化指标。
- 确定性兜底：无 key/LLM 故障时，`TemplateProvider` 仍能从同一组指标渲染出日报。
- 可追溯：LLM 产出的日报文案中每个事实句，都能映射回输入的结构化指标/事件（人工抽查 + 结构化对照测试）。
- 一致性：对同一组指标，`TemplateProvider` 与 `DeepSeekProvider` 产出的日报在**事实数字**上一致（措辞可不同）。
